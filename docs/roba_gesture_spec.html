roBa Trackball Gesture 仕様書

対象: roBa / ZMK / Windows・macOS 両対応キーマップ

Draft トラックボールを使ったジェスチャーレイヤー仕様。Windows と macOS で、できるだけ同じ物理操作から同じ意味の挙動を得ることを目的とする。

1. 目的

roBa のトラックボールを、通常のポインティング・スクロール操作に加えて、ウィンドウ操作やタブ操作のジェスチャー入力として利用する。

既存の mac レイヤー / Windows レイヤー構成を活用し、同じキー・同じトラックボール操作で OS ごとのショートカット差分を吸収する。

2. レイヤー構成

ジェスチャーレイヤーは OS ごとに分ける。

WIN_BASE
MAC_BASE

WIN_WINDOW_GESTURE
MAC_WINDOW_GESTURE

WIN_TAB_GESTURE
MAC_TAB_GESTURE

2.1 レイヤー遷移

ジェスチャーレイヤーへの移動キーは本仕様では固定しない。各 OS のベースレイヤーから、対応する OS 用ジェスチャーレイヤーへ直接移動する。

遷移元遷移先用途
WIN_BASEWIN_WINDOW_GESTUREWindows 用ウィンドウジェスチャー
MAC_BASEMAC_WINDOW_GESTUREmacOS 用ウィンドウジェスチャー
WIN_BASEWIN_TAB_GESTUREWindows 用タブジェスチャー
MAC_BASEMAC_TAB_GESTUREmacOS 用タブジェスチャー

共通ジェスチャーレイヤーにせず、OS 別レイヤーでショートカット差分を定義する。物理キーの割り当てはキーマップ側の実装詳細として扱う。

3. 共通ジェスチャー判定仕様

3.1 入力開始

ジェスチャーレイヤー中にトラックボールの移動量が最小閾値を超えた時点で、ジェスチャー入力を開始する。

if abs(dx) + abs(dy) > start_threshold:
    gesture_active = true

3.2 終了タイミング

ジェスチャー終了は、レイヤーキーを離したタイミングではなく、トラックボールが止まったタイミングで判定する。

no_input_duration >= stop_timeout
→ ジェスチャー確定
→ 必要なキーアップを送信
→ 累積値をリセット
→ レイヤーキーが押されていれば次のジェスチャー待機

初期値の目安:

項目推奨初期値
start_threshold10〜20 カウント
stop_timeout80〜120 ms
direction_ratio2.0
step_threshold60〜80 カウント
max_steps5〜8 回

3.3 4方向強制判定

斜め入力による誤爆を避けるため、方向は上下左右の4方向に限定する。

if abs(dx) > abs(dy) * direction_ratio:
    direction = RIGHT if dx > 0 else LEFT
elif abs(dy) > abs(dx) * direction_ratio:
    direction = DOWN if dy > 0 else UP
else:
    direction = NONE

direction = NONE の場合は、ジェスチャーを発火しない。

4. 移動量と連続操作

左右ジェスチャーは、ウィンドウジェスチャー・タブジェスチャーのどちらも連続移動に対応する。

ただし、短時間で素早く大きく動かした場合は「1回のフリック」とみなし、移動量が大きくても 1 ステップだけ発火する。

4.1 ステップ数判定

if duration < quick_flick_duration:
    steps = 1
else:
    steps = clamp(floor(abs(primary_delta) / step_threshold), 1, max_steps)
項目推奨初期値
quick_flick_duration180〜220 ms
step_threshold60〜80 カウント
max_steps5〜8 回

4.2 挙動例

入力例結果
右に素早くフリックdx=180, duration=120ms右方向 1 ステップ
右にゆっくり長く転がすdx=240, duration=500ms右方向 3〜4 ステップ
少しだけ動かすdx=20閾値未満なら無視
斜めに動かすdx=80, dy=60方向が曖昧なら無視

5.2 Alt / Cmd の保持

Windows の Alt+Tab、macOS の Cmd+Tab は、修飾キーを押したまま Tab を複数回送信し、停止判定時に修飾キーを離す。

gesture start:
    modifier down   // Windows: Alt, macOS: Cmd

while gesture active:
    send Tab or Shift+Tab according to step count

gesture stop:
    modifier up

これにより、アプリ切り替え UI を開いたまま候補を移動し、トラックボール停止時に選択を確定できる。

目的: ブラウザ、VS Code、Cursor、Finder/Explorer などでタブ操作を共通化する。

6.1 割り当て

↓Ctrl + WCmd + Wタブを閉じるなし

macOS でもブラウザや VS Code のタブ切り替えは多くの場合 Ctrl+Tab / Ctrl+Shift+Tab が使える。ただしアプリによっては Cmd+Shift+[ / Cmd+Shift+] の方が自然な場合がある。

7. 実装上の状態管理

ジェスチャー処理は、最低限以下の状態を持つ。

gesture_active: bool
current_layer_type: WINDOW | TAB
accum_dx: int
accum_dy: int
start_time: timestamp
last_input_time: timestamp
last_emitted_step: int
held_modifier: NONE | ALT | CMD | CTRL

7.1 疑似コード

on_trackball_move(dx, dy):
    if not in_gesture_layer:
        pass through as normal pointer input
        return

    accum_dx += dx
    accum_dy += dy
    last_input_time = now

    if not gesture_active and abs(accum_dx) + abs(accum_dy) > start_threshold:
        gesture_active = true
        start_time = now

    if gesture_active:
        direction = resolve_4way(accum_dx, accum_dy)
        if direction in [LEFT, RIGHT] and layer supports continuous move:
            steps = calculate_steps(accum_dx or accum_dy, now - start_time)
            emit_steps_until(steps)

on_timer():
    if gesture_active and now - last_input_time >= stop_timeout:
        direction = resolve_4way(accum_dx, accum_dy)

        if direction in [UP, DOWN]:
            emit_single_action(direction)
        elif direction in [LEFT, RIGHT]:
            ensure_steps_emitted(direction)

        release_held_modifier_if_any()
        reset_gesture_state()

8. OSレイヤー切り替えミス時の安全性

Windows / macOS のベースレイヤーを間違えた状態でジェスチャーレイヤーに入った場合、OS に合わない修飾キー組み合わせが送信される。今回の用途では、基本的にはアプリ切り替え、タスクビュー、デスクトップ表示、タブ操作に限定されるため、ファイル削除や送信などの重大な破壊的操作には直結しにくい。

誤操作パターン想定される結果リスク
Windows で macOS 用ジェスチャーを実行Cmd 相当が Win として扱われ、意図しない OS ショートカットが発火する可能性がある。中
macOS で Windows 用ジェスチャーを実行Alt / Win 相当が Option / Command として扱われ、アプリ切り替えやメニュー操作が意図とずれる可能性がある。中
タブを閉じる操作の誤発火ブラウザやエディタの現在タブが閉じる。多くの場合は再オープン可能だが、未保存編集がある場合は注意が必要。中
左右連続操作の誤発火アプリやタブが複数個切り替わる。低〜中

安全性を高めるため、ジェスチャーレイヤーには削除、送信、保存せず閉じる、強制終了、ログアウト、スリープ、電源操作などの破壊的・状態変更の大きい操作を割り当てない。

8.1 安全設計の指針

  • 上下方向のうち、特に下方向には破壊的操作を置かない。
  • タブを閉じる操作は便利だが、誤操作が気になる場合は別レイヤーまたは通常キーに退避する。
  • OS切り替え状態を確認しやすいように、Bluetoothプロファイル、LED、OLED、または明示的なレイヤー切り替えキーを併用する。
  • 初期実装では「表示・切り替え」系に限定し、慣れてから「閉じる」系を追加する。

9. 設計方針

  • 長フリック・短フリックの別機能化はしない。誤操作を避けるため、機能差ではなく移動ステップ数の差に限定する。
  • ジェスチャー終了はレイヤーキー解放ではなく、トラックボール停止で判定する。
  • 左右方向は連続移動に対応する。
  • 上下方向は単発操作に限定する。
  • 斜め方向は無視し、4方向に強制する。
  • OS差分はジェスチャーレイヤーを Windows / macOS で分けて吸収する。

10. 初期実装の推奨範囲

  1. ウィンドウジェスチャーレイヤーを実装する。
  2. ↑ / ↓ を単発操作として実装する。
  3. ← / → を修飾キー保持型の連続移動として実装する。
  4. タブジェスチャーレイヤーを追加する。
  5. 閾値を実機で調整する。
